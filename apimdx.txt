DOCUMENTAÇÃO BASE - INTEGRAÇÃO API MEDX / AUTOMAÇÃO DE AVISO DE AGENDAMENTO

Objetivo:
Construir uma automação para consultar agendas médicas via API, identificar agendamentos futuros e enviar avisos/lembretes aos pacientes.

Base URL Produção:
https://medx65-v65teste.azurewebsites.net

Padrão da requisição:
JSON

IMPORTANTE:
Nunca expor o token de integração no lado cliente/frontend.
O token de autenticação deve ser usado apenas no backend/servidor.

============================================================
1. AUTENTICAÇÃO
============================================================

Antes de consultar qualquer endpoint, é necessário gerar um token de autenticação.

Método:
GET

Endpoint:
/api/integration/GetAuthorizedToken?token=SEU_TOKEN_INTEGRACAO

URL completa:
https://medx65-v65teste.azurewebsites.net/api/integration/GetAuthorizedToken?token=SEU_TOKEN_INTEGRACAO

Descrição:
SEU_TOKEN_INTEGRACAO é o token obtido no sistema em:
Ajustes > Integração para websites e links

Retorno esperado:
HTTP 200 com uma string contendo o token de autenticação.

Validade do token:
180 minutos.

Exemplo cURL:
curl --location 'https://medx65-v65teste.azurewebsites.net/api/integration/GetAuthorizedToken?token=SEU_TOKEN_INTEGRACAO'

Uso nas próximas chamadas:
Todas as chamadas subsequentes devem enviar o token no header Authorization:

Authorization: Bearer TOKEN_DE_AUTENTICACAO

============================================================
2. CONSULTAR USUÁRIOS DA AGENDA / MÉDICOS
============================================================

Use este endpoint para listar os profissionais/médicos disponíveis na agenda e obter o ID do usuário.

Método:
GET

Endpoint:
/api/integration/GetUsuariosAgenda

URL completa:
https://medx65-v65teste.azurewebsites.net/api/integration/GetUsuariosAgenda

Parâmetros:
Sem parâmetros.

Header obrigatório:
Authorization: Bearer TOKEN_DE_AUTENTICACAO

Exemplo cURL:
curl --location 'https://medx65-v65teste.azurewebsites.net/api/integration/GetUsuariosAgenda' \
--header 'Authorization: Bearer TOKEN_DE_AUTENTICACAO'

Objetivo no sistema:
- Buscar a lista de usuários/médicos.
- Localizar o médico pelo nome.
- Guardar o ID do médico para consultar a agenda específica.

Exemplo de lógica:
1. Consultar GetUsuariosAgenda.
2. Procurar pelo nome do médico desejado, por exemplo: Dra. Marina.
3. Obter o campo de ID do usuário.
4. Usar esse ID no endpoint GetAgendabyUsuario ou GetDisponibilidade.

Observação:
No retorno de GetAgenda foi identificado o campo Id_Usuario em cada agendamento.
Exemplo de IDs encontrados:
- Id_Usuario: -1212054111
- Id_Usuario: 514732650
- Id_Usuario: 578834368

Também foi identificado um registro com:
Quemcriounome: dramarinadedeus
Id_Usuario: -1212054111
Descricao: FECHADA (SEQUENCIAL)

Isso indica que o Id_Usuario -1212054111 provavelmente pertence à Dra. Marina de Deus, mas a confirmação correta deve ser feita via GetUsuariosAgenda.

3. CONSULTAR AGENDA GERAL
============================================================

Consulta todos os agendamentos dentro de um período, sem filtrar por médico.

Método:
GET

Endpoint:
/api/integration/GetAgenda?inicio=YYYY-MM-DD&fim=YYYY-MM-DD

URL exemplo:
https://medx65-v65teste.azurewebsites.net/api/integration/GetAgenda?inicio=2026-06-18&fim=2026-06-30

Parâmetros:
inicio: data inicial
fim: data final

Header obrigatório:
Authorization: Bearer TOKEN_DE_AUTENTICACAO

Exemplo cURL:
curl --location 'https://medx65-v65teste.azurewebsites.net/api/integration/GetAgenda?inicio=2026-06-18&fim=2026-06-30' \
--header 'Authorization: Bearer TOKEN_DE_AUTENTICACAO'

Campos importantes no retorno:
- Id_Usuario: ID do médico/profissional responsável pelo agendamento.
- Inicio: data e horário inicial do agendamento.
- Fim: data e horário final do agendamento.
- Descricao: informações do paciente e observações do agendamento.
- TipoAgendamento: tipo do agendamento, quando disponível.
- Status: status numérico do agendamento.
- Id_Paciente: ID do paciente vinculado.
- Id_Agendamento: ID único do agendamento.
- Confirmacao: informação de confirmação, quando houver.
- SMS: telefone/celular do paciente, quando preenchido.
- Setor: setor do agendamento.
- CreationDate: data de criação do agendamento.
- LastEditDate: data da última alteração.
- Quemcriounome: usuário que criou o agendamento.
- Quemeditounome: usuário que editou o agendamento.

Exemplo de item retornado:
{
  "Id_Usuario": -1212054111,
  "Inicio": "2026-06-30T18:20:00",
  "Fim": "2026-06-30T18:40:00",
  "Descricao": "NOME DO PACIENTE, observações, telefone",
  "TipoAgendamento": null,
  "Status": 0,
  "Id_Paciente": 1211488404,
  "Id_Agendamento": 1890563241,
  "Confirmacao": null,
  "SMS": "34999999999",
  "Setor": "Clínica"
}

17. FLUXO RECOMENDADO PARA AUTOMAÇÃO DE AVISO DE AGENDAMENTO
============================================================

Objetivo:
Enviar aviso automático para pacientes com agendamento futuro.

Fluxo recomendado:

1. Gerar token de autenticação:
   GET /api/integration/GetAuthorizedToken?token=SEU_TOKEN_INTEGRACAO

2. Consultar médicos/usuários da agenda:
   GET /api/integration/GetUsuariosAgenda

3. Definir qual médico será monitorado:
   - Buscar pelo nome do médico.
   - Obter o ID do médico.

4. Consultar agenda do médico:
   GET /api/integration/GetAgendabyUsuario?inicio=DATA_INICIO&fim=DATA_FIM&idUsuario=ID_DO_MEDICO

5. Filtrar agendamentos que devem receber aviso:
   Sugestões de filtro:
   - Agendamentos de amanhã.
   - Agendamentos das próximas 24 horas.
   - Agendamentos ainda não confirmados.
   - Agendamentos com telefone preenchido no campo SMS.
   - Ignorar bloqueios como "FECHADA", "BLOQUEADO" ou agendamentos sem paciente.

6. Extrair dados necessários:
   - Nome do paciente: pode vir no início do campo Descricao.
   - Telefone: preferencialmente campo SMS.
   - Data e hora: campo Inicio.
   - Médico: pelo Id_Usuario cruzado com GetUsuariosAgenda.
   - ID do agendamento: Id_Agendamento.
   - Status: campo Status.
   - Confirmação: campo Confirmacao.

7. Enviar mensagem de aviso:
   Exemplo de mensagem:
   Olá, {nome_paciente}. Passando para lembrar do seu agendamento com {nome_medico} no dia {data} às {hora}. Caso precise remarcar, responda esta mensagem.

8. Registrar que o aviso foi enviado:
   Criar controle interno para evitar envio duplicado.
   Sugestão: salvar em banco de dados ou arquivo local:
   - Id_Agendamento
   - Data/hora do envio
   - Telefone
   - Status do envio

9. Opcional: confirmar agendamento via UpdateAgendamento:
   Se o paciente responder confirmando, atualizar o agendamento usando:
   PUT /api/integration/UpdateAgendamento
   Campo Confirmacao deve ser exatamente:
   Mensagem Salva com Sucesso

============================================================
18. REGRAS IMPORTANTES PARA A AUTOMAÇÃO
============================================================

- Não enviar aviso para agendamentos sem telefone.
- Não enviar aviso duplicado para o mesmo Id_Agendamento.
- Tratar token expirado: se receber erro de autenticação, gerar novo token.
- Considerar timezone local do Brasil ao comparar datas e horários.
- Validar se o campo SMS está preenchido e normalizar telefone para envio no WhatsApp.
- Ignorar agendamentos de bloqueio, por exemplo:
  Descricao contendo "FECHADA", "BLOQUEADO", "SEQUENCIAL" ou sem paciente vinculado.
- Conferir se Id_Paciente é diferente de 0 quando for obrigatório enviar apenas para pacientes vinculados.
- Tratar Status conforme regra da clínica.

19. EXEMPLO DE PROMPT PARA CLAUDE CODE
============================================================

Crie uma automação em Node.js para consultar a API MedX e enviar lembretes de agendamento.

Requisitos:
1. Usar variáveis de ambiente para BASE_URL, TOKEN_INTEGRACAO e dados do provedor de envio WhatsApp.
2. Criar função getAuthToken() chamando /api/integration/GetAuthorizedToken.
3. Criar função getUsuariosAgenda() para buscar os médicos.
4. Criar função findMedicoByName(nome) para localizar o médico pelo nome e retornar o ID.
5. Criar função getAgendaByUsuario(idUsuario, inicio, fim) para consultar os agendamentos do médico.
6. Filtrar agendamentos das próximas 24 horas ou do dia seguinte.
7. Ignorar registros sem SMS, sem Id_Paciente ou com descrição contendo FECHADA/BLOQUEADO/SEQUENCIAL.
8. Extrair nome do paciente a partir do campo Descricao.
9. Formatar data e hora em padrão brasileiro.
10. Enviar uma mensagem de lembrete para o telefone do campo SMS.
11. Criar controle de envios para não repetir o mesmo Id_Agendamento.
12. Tratar erros de token expirado, falha de API e falha de envio.
13. Gerar logs simples no console.
14. Deixar o código organizado em funções.

Mensagem padrão:
Olá, {nome_paciente}. Passando para lembrar do seu agendamento com {nome_medico} no dia {data} às {hora}. Caso precise remarcar, responda esta mensagem.
